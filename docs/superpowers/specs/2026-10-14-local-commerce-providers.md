# Offline Commerce routing adapters

Authorized scope: optional operator-only Laya/GLiClass routing after bundled
assessment. User authorizes implementation and comparison without mandatory
exercises or review gates. Rules/browser/API/worker and business invariants stay.

Reuse cached pinned loaders and flat single-label GLiClass ranking. Model features
are task, seven normalized tri-state facts and allowed choice descriptions only;
identifiers, bindings and audit versions never become features. One-choice local
requests settle a forced deterministic recommendation with zero dispatches.

Extend existing typed contracts with pinned local configuration and native timing/
score/resource metadata. Local accounting has explicit no-API-charge pricing and
unknown token counts. Keep fake simulated pricing and historical traces readable.
Existing migration0005 is sufficient: no business DDL changes. Atomic count budget,
immutable run/config, deadline, stale-result checks and no uncertain redispatch stay.

Each CPU family runs in its own bounded subprocess, batch1, four threads, offline
flags before model imports. Loading/startup is inside the deadline (up to120s).
Kill/reap the process group on timeout. Optional dependencies remain locked; use
existing model environment if supplied. No downloads/upgrades or real API/cloud.

Only the all-true state permits a scored decision; there are 3^7 tri-state vectors
but 2186 are forced review. Report distinct model inputs and this degeneracy.
Small offline integration/reference-rule agreement, not held-out generalisation.
Persist native scores/uncalibrated meanings, model revision, load/inference/wall
seconds, peak RSS, actual routing effect and failures. Preserve negative results.
